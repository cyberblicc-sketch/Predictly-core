1. PROJECT OVERVIEW
================================================================================

Supreme Fusion is a production-ready prediction market platform built for a
solo developer. It features dual-currency (Gold Coins + Sweeps Coins), atomic
PostgreSQL transactions, AI trading agents, KYC verification, referral system,
and a full admin dashboard.

KEY FEATURES:
- Dual Currency System: GC (purchased) + SC (free promotional)
- LMSR Market Making: automated liquidity with 3% total fee (2% + 1%)
- Atomic Transactions: RPC functions with row locking prevent double-spend
- AI Trading Swarm: 4 agents (Momentum, Contrarian, Arbitrage, Sentiment)
- KYC via Stripe Identity: only at redemption (min 50-60 SC)
- Referral System: +20 SC + 20,000 GC per depositing referral
- Fraud Reporting: user-submitted reports on any market
- Social Sharing: Twitter, Telegram, Facebook share buttons
- Admin Dashboard: full CRUD, audit logs, AI controls, dispute resolution
- Leaderboard: global rankings by total winnings

4. KEY RPC FUNCTIONS (003_rpc_functions_and_tables.sql)
================================================================================

process_stake(p_user_id, p_market_id, p_side, p_amount):
- Validates SC balance >= stake amount
- FOR UPDATE row lock on market (prevents race conditions)
- Deducts SC from user, adds to YES or NO pool
- Creates position record with entry_price from LMSR
- Logs transaction as STAKE type
- Returns position_id, entry_price, new probability

resolve_market(p_market_id, p_outcome, p_resolution_source):
- Validates market is open and not already resolved
- FOR UPDATE lock on all positions for market
- Calculates total pool (yes_pool + no_pool)
- Distributes winning side pool to winning positions pro-rata
- Records PAYOUT transactions for winners
- Applies house_fee and platform_fee to platform ledger
- Updates market status to resolved

apply_referral_reward(p_referrer_id, p_referred_user_id, p_deposit_amount):
- Validates referral exists and referred user made deposit
- Credits +20 SC + 20,000 GC to referrer
- Updates referral status to completed
- Logs transaction as REFERRAL_REWARD type

redeem_kyc(p_user_id, p_amount, p_method):
- Validates user KYC status is verified
- Validates amount >= 50 SC (gift card) or >= 60 SC (USD transfer)
- Converts SC to USD at 1 SC = $0.01
- Creates Stripe payout intent
- Deducts SC from user balance
- Logs transaction as KYC_REDEMPTION type

update_market_probability():
- Computes YES probability as: yes_pool / (yes_pool + no_pool)
- Updates current_probability column on all open markets
- Called by AI swarm tick or scheduled job

redeem_position(p_position_id, p_user_id):
- Allows early exit at current probability
- Deducts 2% exit fee if position is profitable
- Updates position status to closed
- Logs transaction as STAKE (reversal) type

6. AI SWARM ARCHITECTURE
================================================================================

Model: Groq llama-3.3-70b-versatile (14k tokens/min free tier)

Agent Types:
- Momentum: Follows price trends (buy YES if trending up)
- Contrarian: Bets against overreactions (profitable on overreaction)
- Arbitrage: Exploits probability mismatches across markets
- Sentiment: Analyzes Twitter/news for market sentiment

Rate Limits:
- Max 10 trades per 5-minute tick
- Max 50,000 SC per agent per day
- Confidence threshold: 0.7 minimum
- Markets < 1 hour to close: skipped

Safety:
- Manual kill switch via ai_swarm_config.enabled flag
- Daily loss limit per agent
- All trades logged to ai_agent_trades table
- Transparent: users can see all AI activity

Execution Flow:
1. pg_cron triggers ai-swarm-tick every 5 minutes
2. Edge Function fetches open markets with recent activity
3. For each market, Groq receives JSON analysis prompt
4. Groq returns 4 agent decisions in structured format
5. Trades executed atomically via process_stake() RPC
6. All trades logged for transparency

KYC Verification (Stripe Identity):
- Triggered only at redemption time
- ~$10 per verification paid by platform
- PII handled by Stripe; we store only status + document URL

Redemption Flow:
1. User requests redemption (min 50-60 SC)
2. Stripe Identity SDK embedded on /auth/kyc-verify
3. User captures government ID
4. Stripe processes asynchronously
5. Webhook received at /api/webhooks/stripe
6. User kyc_status updated to 'verified'
7. Redemption enabled

16. TECHNOLOGY CHOICES & RATIONALE
================================================================================

Why Next.js 16 App Router?
- Server Components for SEO + performance
- Route groups for clean code organization
- Edge runtime for global latency
- TypeScript first-class support

Why Supabase (not PlanetScale/Firebase)?
- Free tier: 500MB Postgres, 50k MAU
- Row Level Security built-in
- Real-time subscriptions for live updates
- Auth + Storage + Edge Functions in one platform

Why Groq for AI?
- Free tier: 14k tokens/min
- Llama 3 70B competitive with GPT-3.5
- Sub-second inference (fast for frequent ticks)

Why Stripe Identity (not other KYC providers)?
- Industry standard, well-documented
- Handles PII compliance
- Only pay when users redeem (not at signup)

Why RPC > Edge Functions for core logic?
- Atomic transactions (all-or-nothing)
- Performance (runs in DB process)
- RLS enforced transparently
- Immutable audit trail
